# 国产化智能资产运营平台项目计划书

## 1. 项目概述

### 1.1 临时项目定义

本项目基于现有资产管理系统进行国产化智能升级，面向资产管理员、采购人员、接收部门和管理层，解决资产数据分散、闲置资产难盘活、采购缺少历史依据、维修与工单数据未形成决策依据等问题。

核心交付物：资产全生命周期管理、闲置调拨闭环、品牌与型号表现分析、采购建议、管理驾驶舱、报告中心，以及统一的 AI 辅助能力。

### 1.2 当前基线

- 已有 Vue 3 + Vite + Element Plus 前端。
- 已有 FastAPI 后端和 MySQL 数据库。
- 已有资产、字典、用户、资产流转、盘点记录、预警、报告和 AI 配置模块。
- 已有源系统同步机制。
- `ai_asset_transfer.bill_type = 10700` 稳定表示维修工单，`fee` 表示维修费用。
- 当前未确认存在结构化用户满意度数据，因此第一期不将满意度作为评分指标。

## 2. 目标与成功标准

### 2.1 业务目标

1. 建立从资产入账、使用、维修、调拨、盘点、到期和报废的可追溯管理链路。
2. 让闲置识别可以转化为管理员与接收部门确认的调拨业务。
3. 使用维修、工单、闲置、盘点和报废数据辅助品牌、型号和采购决策。
4. 让 AI 负责自然语言理解、解释和报告组织，数字计算、权限判断和写入由后端规则完成。
5. 满足国产化部署和后续国产数据库替换的适配要求。

### 2.2 可量化成功标准

- 登录后 10 秒内可看到待处理风险、闲置和采购洞察。
- 一条调拨建议可以创建、接收部门确认/拒绝、管理员执行，并完整保留变更前后值。
- 品牌和型号指标均能追溯到资产或维修工单明细。
- 采购建议能展示可调拨数量、采购缺口、候选型号、预算和推荐依据。
- AI 不可用时，规则化查询、统计和调拨流程仍可使用。
- 国产操作系统可部署；数据库访问不依赖不可替换的 MySQL 专有语法。

## 3. 范围

### 3.1 本期范围

- 资产全生命周期档案和资产检索。
- 闲置资产识别、调拨建议、双方确认、管理员执行和审计。
- 维修工单及费用统计。
- 品牌表现、型号表现和数据依据明细。
- 采购需求预测和采购建议单（先生成建议，不自动下采购单）。
- 驾驶舱、待办与洞察、报告中心。
- 统一 AI 配置、自然语言查询、采购需求理解、推荐解释和报告润色。
- 用户、角色、数据范围、同步任务和操作审计。

### 3.2 明确不纳入本期

- AI 自动修改资产主数据。
- 无人工确认的批量调拨或采购下单。
- 直接替代财务、采购审批系统。
- 没有数据依据的品牌绝对排名。
- 用户满意度评分，除非后续确认并接入评价数据。

## 4. 业务流程设计

### 4.1 闲置调拨

```text
识别闲置资产 -> 管理员创建建议 -> 接收部门确认/拒绝
-> 管理员执行 -> 更新部门/位置/使用人 -> 写入审计记录
```

执行前必须重新检查资产版本、当前状态和是否被其他建议占用，防止覆盖并发修改。

状态：`draft`、`pending_receiver`、`rejected`、`confirmed`、`completed`、`cancelled`。

### 4.2 采购决策

```text
需求描述 -> 识别类别和场景 -> 检索可调拨资产 -> 计算采购缺口
-> 比较品牌/型号表现 -> 输出候选和预算 -> 人工确认采购建议
```

## 5. 指标与评分口径

比较范围必须限定为同一资产类别、相近使用年限和可比较的使用场景。

基础指标：资产数量、在用数量、闲置率、维修工单数、维修频率、累计维修费用、单资产维修成本、平均使用年限、提前报废率、盘点异常率、单位年成本和样本量。

维修数据来源：`ai_asset_transfer`，条件为 `bill_type = 10700`，按 `asset_id` 关联 `ai_asset`，维修费用使用 `fee`。

辅助评分：

```text
可靠性 35% + 全生命周期成本 25% + 闲置与适配表现 20%
+ 盘点稳定性 10% + 样本可信度 10%
```

评分不能替代指标明细。样本不足、维修数据不完整或关键字段缺失时，必须显示风险标签，不得按零值处理。

## 6. AI 设计原则

- 通过统一适配层调用线上 OpenAI-compatible 接口或本地模型。
- AI 负责自然语言理解、需求结构化、结论解释和报告文字组织。
- 后端负责筛选、聚合、评分、金额、数量、权限和数据写入。
- AI 不直接生成或执行 SQL，不直接修改资产主数据。
- 每个 AI 结论必须返回数据依据、统计时间范围和模型状态。
- 模型不可用时提供规则化兜底，并在界面明确标识。
- API Key 只写入服务端配置，不返回明文。

## 7. 技术架构

```text
Vue 3 / Element Plus
        |
FastAPI API 层
        |
业务服务层（调拨、分析、采购、报告、同步）
        |                    \
数据访问适配层              AI 适配层
        |                    /
国产数据库 / MySQL兼容     线上模型 / 本地模型
```

推荐继续使用现有 Vue 3 + FastAPI，避免没有必要的整体重写；通过数据访问适配、配置外置和容器化满足国产化迁移要求。

数据库首选目标为达梦或 openGauss，开发阶段保留 MySQL 兼容环境。最终数据库以用户的国产化验收目录为准，不能仅凭操作系统国产化认定项目完成国产化。

部署目标：openEuler、麒麟或统信 UOS；容器化部署，配置、日志、备份和密钥独立挂载。

## 8. 权限与审计

- 管理员：配置、同步、执行调拨、维护基础数据。
- 资产管理员：创建调拨建议、查看分析和采购建议。
- 接收部门：确认或拒绝调拨建议。
- 采购人员：查看和确认采购建议。
- 管理层：查看驾驶舱、报告和汇总分析。
- 所有资产字段写入必须记录操作人、时间、原因、原值和新值。
- 数据范围继续由后端统一控制，不能仅依赖前端隐藏菜单。

## 9. 分阶段计划

### 阶段 0：数据和环境核验

核对维修工单关联、费用、时间范围、字段完整性、数据库兼容性和国产化运行环境。

验收：输出数据质量报告和待修复清单。

### 阶段 1：调拨建议闭环

实现数据模型、状态流转、双方确认、执行写入、并发校验和审计。

验收：完整走通创建、确认、执行、拒绝和取消流程。

### 阶段 2：品牌与型号表现

实现指标接口、评分规则、品牌/型号页面和证据明细。

验收：任一指标可追溯到资产或维修工单记录。

### 阶段 3：采购建议

实现需求、闲置可调拨量、采购缺口、候选型号、预算和建议单。

验收：同一需求可生成可解释的候选方案，且不自动下单。

### 阶段 4：AI 场景接入

接入需求理解、推荐解释、资产风险说明和报告生成；完善模型失败兜底。

验收：记录模型调用状态，AI 不可用时核心业务仍可执行。

### 阶段 5：国产化适配与交付

完成国产操作系统、目标数据库、容器部署、备份恢复、日志和安全检查。

验收：按部署清单完成安装、启动、数据迁移和回滚演练。

## 10. 主要风险与待验证项

| 风险 | 影响 | 处理方式 |
|---|---|---|
| 维修工单编码或同步范围变化 | 品牌评分失真 | 同步校验、类型字典和数据质量告警 |
| 品牌/型号命名不规范 | 比较结果分裂 | 归一化字段和人工确认的归并建议 |
| 样本量过小 | 误导采购 | 最小样本量和“样本不足”标签 |
| 调拨并发修改 | 覆盖最新资产信息 | 版本/更新时间校验和事务更新 |
| AI 返回格式不稳定 | 解释或查询失败 | 结构化输出校验和规则兜底 |
| 国产数据库兼容差异 | 部署或查询失败 | 数据访问适配层、兼容 SQL 测试集 |
| 国产化验收目录未明确 | 选型返工 | 尽早确认 OS、数据库、中间件和密码算法要求 |

## 11. 关键决策记录

- 保留 FastAPI，不进行无必要的后端整体迁移。
- AI 使用统一适配层，不绑定单一模型供应商。
- 调拨采用“接收部门确认 + 管理员执行”，暂不引入多级审批。
- 调拨完成后允许直接修改资产所属部门、位置和使用人。
- 采购建议先生成业务建议，不自动触发采购。
- 第一版品牌分析使用维修、工单、闲置、报废和盘点数据，不使用未经确认的满意度数据。
- 国产数据库具体产品仍需结合验收目录最终确认，这是永久性部署约束。
