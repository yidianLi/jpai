# Stage 2：品牌与型号表现分析

## 已实施

- 新增 `GET /api/insight/brands` 和 `GET /api/insight/models`。
- 指标基于 `ai_asset` 与 `ai_asset_transfer` 聚合，维修工单固定使用 `bill_type = 10700`。
- 返回资产数、维修工单数、维修费用、闲置率、维修频率、样本量、可信度和风险标签。
- 新增“采购决策分析 / 品牌表现”页面及二级菜单。
- 增加型号证据查询 `GET /api/insight/models/evidence` 和 AI 解释接口 `POST /api/insight/explain`；解释失败时返回规则提示。
- 当前品牌字段有效率约 0.02%，维修工单有效关联为 0，页面会展示数据不足，不生成综合推荐分数。

## 验收

- 后端 Python 编译通过，`/api/insight/brands`、`/api/insight/models` 路由已注册。
- 前端生产构建通过。
- 后端已重启，`/health` 返回 `ok`。

## 数据质量门槛

在品牌字段和维修关联数据补齐前，仅允许展示运营表现和缺失提示；不得把缺失维修记录当作零维修，也不得输出“最佳品牌”结论。

## 后续

补齐源系统品牌字段、维修工单资产关联和维修费用后，再增加时间范围、类别/部门筛选、型号证据明细和综合评分。随后进入 Stage 3 采购建议。
