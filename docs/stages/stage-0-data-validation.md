# Stage 0：数据与环境核验清单

## 目标

确认维修工单、资产品牌/型号、维修费用和时间范围的数据口径，建立后续品牌/型号分析的基线；同时记录国产化部署和数据库兼容性待验证项。

## 代码端任务

1. 新增只读核验脚本或管理命令，不修改业务数据。
2. 统计 `ai_asset` 总资产数、品牌缺失数、型号缺失数、购置日期缺失数。
3. 统计 `ai_asset_transfer` 中 `bill_type = 10700` 的工单总数、关联资产数、未关联资产数、维修费用合计、费用缺失数和最早/最晚工单日期。
4. 按品牌、型号和资产类别统计资产数、维修工单数、维修费用、闲置数和报废数。
5. 计算维修工单与资产的关联率，随机抽取 10 个资产输出资产信息与维修明细，供人工和源系统核对。
6. 检查迁移脚本中是否使用 MySQL 专有语法；标记 `AUTO_INCREMENT`、`JSON`、日期函数和分页语法的兼容风险。
7. 输出 Markdown 或 JSON 核验报告，报告不得包含 API Key、数据库密码和完整敏感个人信息。

## 必须固定的统计口径

- 维修记录：`ai_asset_transfer.bill_type = 10700`。
- 维修金额：`fee`，空值按“缺失”统计，不按 0 计入质量判断。
- 资产关联：`ai_asset_transfer.asset_id = ai_asset.asset_id`。
- 品牌/型号比较：先按 `class_id` 或类别路径分组，再比较品牌和型号。
- 统计时间：维修指标按 `bill_date` 筛选；资产年龄按 `buy_date` 计算。
- 样本量：品牌或型号少于 10 台时标记“样本不足”，不得输出强推荐。

## 交付文件

- 核验脚本或命令文件路径。
- 核验报告路径。
- 数据异常清单。
- 国产数据库/操作系统待验证清单。

## 验收标准

- 抽取的 10 个资产维修次数和费用与源系统一致，或明确列出差异及原因。
- 维修关联率、费用缺失数和品牌/型号分布可由 SQL 复算。
- 无任何写操作、表结构变更或生产数据修改。
- Python 编译检查、脚本运行检查和 `git diff --check` 通过。

## 代码端完成后必须返回

1. 修改/新增文件清单。
2. 执行命令和运行环境。
3. 核验结果摘要。
4. 未解决的数据问题和对 Stage 1/2 的影响。
